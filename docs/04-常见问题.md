# 04 · 常见问题（FAQ）

## 安装类

### Q: 粘贴脚本后报 `Uncaught SyntaxError: Unexpected token ')'`

粘贴被截断了。这个脚本 6000 多行、约 280KB，浏览器脚本编辑器的剪贴板有概率截断。
**改用文件导入**：[02-脚本版安装教程](02-脚本版安装教程.md) 第 3 步的方式 1 或方式 2。

判断方法：装好后看 Tampermonkey 里脚本的行数，应该是 **6000+ 行**；只有几百行就是截断了。

### Q: 扩展加载时报 `Manifest file is missing or unreadable`

你选到了 zip 或上层目录。必须选中**解压后含 `manifest.json` 的那一层文件夹**。

### Q: 页面右上角没有悬浮面板

1. 先 `F5` 刷新页面（脚本只在文档加载时注入）
2. 确认当前域名在匹配列表里：`chaoxing.com`、`xuexitong.com`、各校镜像（`*.edu.cn` 等）
3. 面板可能被折叠了，按 **F9** 试试，或者看页面右下角有没有半透明条
4. 扩展版：检查浏览器版本是否 ≥ 111

### Q: 油猴脚本和扩展能不能一起装？

不能。会重复注入，两套面板互相抢答题，表现为卡住或跳题。**只留一个。**

## 账号池 / 余额类

### Q: 控制台一直显示 `账号池: 0 个号`，等很久也没有 `铸号成功`

本版本不带预设账号，全靠后台通过公共 CORS 中转注册新号。以下情况会导致暂时造不出来：

- 中转站（`cors.eu.org` / `allorigins` 等）对你这个 IP 限流了（HTTP 429）
- 中转站本身挂了（HTTP 5xx / 超时）
- 该中转出口 IP 已经被人领过 20 分（返回 `score: 0`）

脚本的处理：429 冷却 3 分钟、超时冷却 1 分钟、0 分冷却 10 分钟，连续失败还会指数退避（最长 5 分钟一轮）。

**你能做的：**

1. 等 2~5 分钟，让它自己换站重试
2. 换个网络（手机热点、切 WiFi）再刷新页面，出口 IP 变了成功率会高很多
3. 多用几个常用中转：脚本会自动挑选本地记录里命中率最高的那个

### Q: 后台补池好像只跑了一次，之后就不动了

3.2.10 已修复：旧版用 `setInterval` + 失败时重排定时器，某轮请求卡住（`busy` 没释放）或定时器被重排丢掉后就不再跑。
现在改成 **15s 固定心跳 + 75s 看门狗 + 跨 iframe 互斥**，即使某轮失败也会按 27s → 49s → 87s（上限 2 分钟）继续重试。

如果你用的还是 3.2.9，请更新脚本。判断方法：控制台应出现

```
[CRACK] 后台补池已启动：目标 200 分，每 15s 心跳，不足时自动补充
[CRACK] keeper 心跳：池 N 个号 / M 分，开始补
```

第二种日志每隔几十秒就会出现一次。


因为 **池内积分已经够了**。Keeper 的规则是：池内总积分 ≥ `poolTarget`（默认 200）就不铸号 —— 这是刻意设计，
不是坏了。3.2.11 起它会每分钟打一条心跳证明自己活着：

```
[CRACK] keeper 心跳：池 160 个号 / 3174 分 ≥ 目标 200，无需补充
```

看到这条就说明 Keeper 在正常跑。等你把积分刷到 200 以下，就会看到 `keeper 心跳：池 N 个号 / M 分，开始补`。

想让它一直补，把 `poolTarget` 调大（比如 3000）即可；想连着补，把 `keeperHeartbeat` 调小。

### Q: 铸号日志里全是 `http=-1`，一个 `429` 都没有

`http=-1` 是**网络层就被拦住**了，请求根本没发出去。最常见原因：

1. **Tampermonkey / ScriptCat 的 `@connect` 白名单**（3.2.11 及更早版本）
   旧版 header 只放行了 `911285.xyz`、`gptjs.808860.xyz`、`127.0.0.1`，
   中转站 `cors.eu.org` / `api.allorigins.win` / `api.cors.lol` 全部被脚本管理器直接拒绝 → 一律 `-1`。
   **3.2.12 已加 `@connect *` 修复**，升级即可。
2. 本机代理 / 防火墙拦了中转域名（挂了科学上网的分流规则时偶发）
3. 中转站自己挂了（`cors.eu.org` 有过返回 Cloudflare 拦截页的情况）

判断方法：升级到 3.2.12 后再看日志，
- 出现 `http=429` / `http=408` / `http=5xx` → 请求已经在正常发出，只是被中转限流，等或换网络
- 还是 `-1` → 检查代理规则 / 脚本管理器的 @connect

### Q: 面板上的「账号池」那行一直是 0，但控制台在刷铸号失败

说明公共中转对你这个出口 IP 限流了（`http=429` / `http=-1` / `http=408`）。
脚本会自动冷却+换站+退避，但短期内造不出号。**换个网络最有效**：

- 手机开热点给电脑连，刷新页面 → 新 IP，通常立刻能铸到 2~3 个号
- 或者等 10~30 分钟再试

提示「所有中转都在冷却中，Xs 后恢复」也是同一件事，等它恢复即可。

### Q: 池里明明有号，为什么看不到补池日志 / keeper 不动了

因为**池内积分已经够了**。Keeper 规则：池内总积分 ≥ `poolTarget`（默认 200）就不铸号，这是刻意设计。

3.2.11 起它会**每分钟打一条心跳**证明自己活着：

```
[CRACK] keeper 心跳：池 160 个号 / 3174 分 ≥ 目标 200，无需补充
```

看到这条就说明正常。等你把积分刷到 200 以下，会出现 `keeper 心跳：池 N 个号 / M 分，开始补`。

- 想让它一直补：把 `poolTarget` 调大（比如 3000）
- 想补得更勤：把 `keeperHeartbeat` 调小（比如 8000）

### Q: 提示「账户余额不足，请充值」

这是**原版脚本**的报错，说明这一题走到了回退逻辑（免费通道 + 账号池都没拿到答案）。

原因通常是池子空了。等后台补到号再重试即可。

### Q: 为什么每道题前面还要多等几秒？

配置里 `mintFirst: true`：每题会先花最多 6 秒试一次"现注册新号"，成功了立刻用新号答（20 分额度）。
不成功就回落到账号池。不想等可以改成 `mintFirst: false`，直接走账号池。

### Q: 想让我自己的学习通账号参与？

本版本不写死任何账号，也不读写你的学习通 cookie。
你的学习通 UID 会出现在面板上（仅供充值页跳转用），但破解逻辑不依赖它。

## 答题类

### Q: 答案填错了 / 选项对不上

- 确认模型是 `GPT-4.1 (普通｜低价)`（唯一免费档位）
- 判断题、多选题的格式由原版脚本处理，复杂题型（填空、连线、听力）成功率天然更低
- 面板设置里可以把「间隔」调大（5~8 秒），给 AI 更多时间

### Q: 能不能用 GPT-6.1 / Claude / Gemini

不能。那些档位服务端强制月卡（`400 请充值月卡后使用`），免费通道和新注册号的 20 分都进不去。

### Q: 考试会不会被发现

技术层面：脚本是页面内正常请求，不修改提交包结构。
但**平台可能有行为分析**，且这属于违反学校规定的行为。请自己评估，本项目不背书任何使用场景。

### Q: 答案质量如何

服务端 `GPT-3.5` 档位实际映射为大模型普通档（约 GPT-4.1 级别）。
选择题、判断题、简单简答基本可用；需要推理的长答题建议人工核对。

## 性能 / 网络类

### Q: 一道题要 20~60 秒才出答案

说明正在现铸账号（`crackMint`）+ 中转超时重试。池子里有号的时候是 1~4 秒。
想稳定快就多等一会儿让池子攒起来，或者换网络。

### Q: 会不会把浏览器卡死

不会。大量网络请求是并发的且都有超时（默认 15~25 秒），后台任务每 45 秒一次。

### Q: 数据存在哪

浏览器本域 `localStorage`（键名 `gptjs_gm_*` / `GPTJsCrack.*`），只在你本机。
